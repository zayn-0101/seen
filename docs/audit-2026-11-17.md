## 本轮已修复（2026-11-17 审计修复）

- **实例锁原子化**：`core/lib/index.js` 先把 owner 写入唯一临时目录，再用 `renameSync` 原子替换/创建 `instance.lock` 目录，避免空锁窗口；清理陈旧锁前核对目录 inode/dev，只删除自己的 owner 文件再 `rmdir`，非空目录不删，避免误删其他进程刚创建的新锁；同 PID 重复启动按占用处理。拿不到锁的进程进入只读模式，`getStatus()` / `getConfig()` 返回 `readOnly` 与 `readOnlyReason`（`locked-by-other` / `lock-write-failed` / `lock-stale-unlink-failed` / `state-unreadable`），面板按原因显示提示。
- **存档重整理离线化**：`resummarizeNote` 现在只读 `资料/字幕/<笔记名>.md` 存档，传 `archiveOnly:true` + `prefetchedContent` 给 `processTitle`，不重新抓平台内容、不下载音频、不转写；缺元数据时从原笔记和状态补齐。
- **无身份笔记覆盖防护**：`core/lib/obsidian.js` 的 `trustedLegacy` 只在目标视频身份明确（bvid/videoId 匹配）时才信任同路径旧笔记；`core/lib/index.js` 只把身份匹配的历史记录作为 `previousNotePath` 依据，避免重刷另一条无身份视频时覆盖同名手写笔记。
- **状态路径归一化**：新增 `core/lib/paths.js` 的 `normalizeAuxRelPath` / `normalizeStateAuxPaths`，启动时修正旧字幕路径；`scripts/migrate-vault.mjs --state-only` 可单独修状态（写回前先备份 state.json）；`scripts/self-check.mjs` 增加字幕路径缺失/遗留检查。
- **供应链校验**：ffmpeg-static 固定 `b6.1.1` 并在 `core/lib/whisper.js` 内置各平台 SHA256，不匹配中止；yt-dlp 的 `SHA2-256SUMS` 只从官方取得，任何来源取不到校验值或校验不符都中止；下载 asset 按平台和 CPU 架构选择（linux arm64 用 `yt-dlp_linux_aarch64`，win32 arm64 用 `yt-dlp_arm64.exe`），官方没有可直接安装二进制的平台明确报错而不是装错架构；`menubar/build.sh` 下载 Node 运行时后用 `SHASUMS256.txt` 校验。
- **搜索可见性**：`core/lib/vault-search.js` 新增 `searchVaultDetailed`，返回 `{ results, scanned, skipped, truncated }`；中文查询用 `Intl.Segmenter('zh')` 分词；面板提示截断和跳过数量。
- **学科上限**：`core/lib/subject.js` 达到 12 个学科且没有相似学科时归入「未分类」，不再强行塞进某个已有学科；`resolveSubjectName(subject, existing, { maxSubjects })` 透传上限。
- **本机 API 防护**：`server/index.js` 的所有 API 请求始终校验 Host / Origin / Sec-Fetch-Site，POST 还要求 JSON content-type，防 DNS rebinding 和跨站调用；只允许绑定本机回环地址，`SEEN_HOST` 设为其他地址会拒绝启动，不做局域网无认证监听；删除兼容用的 `GET /api/llm/models`，只保留 POST，避免自带密钥出现在 URL。
- **保存失败可见**：`save()` 返回布尔值，状态保存失败时笔记仍然返回，但 `warnings` / `stateSaved` 会带给调用方和 SSE；学习手册、课程总览、字幕存档失败也逐项收集警告。
- 同步更新 `README.md`、`CLAUDE.md`、`docs/architecture.md`、`docs/contracts.md` 中关于实例锁、供应链校验、搜索、学科上限和存档重整理的说明。

### 2026-11-18 复审后的追加修复

- 崩溃恢复完整化：`reconcilePendingState` 从已写笔记的 frontmatter 与 callout 回填 summary / question / answer / tags / concepts / quality / contentType / review，恢复后重建索引；扫描未完成或身份有歧义时保留 pending，不再因为 `noteRoot` 写成 `./视频笔记` 或切换布局就误删恢复记录。
- 字幕归属审计补强：`transcript-audit` 把 `state.transcriptPath` 与存档 owner 交叉核对，指向别人的存档报 `state-transcript-owner-mismatch`；路径非法或指向字幕目录外已存在文件分别报 `state-transcript-invalid` / `state-transcript-outside-archive`，单条坏路径不会中止整次审计；字幕目录改为直接安全读取，目录符号链接指向 vault 外部时报 `archive-dir-unreadable`，不再静默跳过整棵目录。
- vault 不可访问语义：`readVaultText` 把 vault 根缺失映射为 `vault-unavailable`，只有文件真正不存在才是 `not-found`；`pendingReviews` 仅在 `not-found` 时删除，避免临时不可访问导致恢复记录丢失。
- 无主存档读取收紧：`readTranscriptNote` 在目标没有 owner 时，必须显式 `allowUnowned:true` 才返回有主或无主的 base 存档；契约同步，避免把别人的存档当成自己的。
- 复习落盘失败：`recordReview` 在笔记写入抛错（超时、权限、EISDIR 等）时保留 pending 并返回 `pendingSaved:true`，因为底层 I/O 可能已经完成；明确返回失败（笔记不存在、无 frontmatter）才按原逻辑删除 pending。
- 崩溃恢复同身份合并：`reconcilePendingState` 跨学科按 bvid+page / videoId+source 收集同一身份记录，notePath 完全一致优先；有记录时从笔记回填并合并摘要、问答、标签、概念、质量与复习进度，删除重复记录、必要时迁到新学科，不再因为路径相同就跳过回填、也不再产生第二条 history。
- 权限恢复补跑：`ready` 与 `reprobeVault()` 共用 `schedulePendingRecovery`，首次 `vaultAccess` 超时导致启动时无法恢复的 pending，会在重新探测成功后立即补跑，不必等下次重启。
