# 拾影项目审查记录 · 2026-11-17

审查基于 `main` 的 `916b977`，覆盖应用核心、网页、菜单栏、测试、文档和构建脚本。以下是本轮修复后仍需处理或决策的事项；未对真实笔记库、真实模型账号或视频平台进行在线回归，也不能由此证明项目不存在其他问题。

## 待审查事项

| 优先级 | 问题与影响 | 建议下一步 |
| --- | --- | --- |
| 高 | **历史字幕可能已发生同名覆盖。** 原实现只按笔记名写入字幕，跨学科同名时会覆盖先前存档。现在新写入会保留副本；重整理会核对归属，有同名记录的无归属旧存档也会被拦下。历史存档是否受影响尚未核实。见 [obsidian.js](../core/lib/obsidian.js) 与 [index.js](../core/lib/index.js)。 | 先制定只读检查，比较状态、字幕的 `notePath`、视频 ID 与现有备份；确认结果后再决定是否恢复。无归属、但状态中只剩一条同名记录的旧存档仍无法保证来源正确。 |
| 高 | **实例锁存在竞态。** [index.js](../core/lib/index.js) 先检查 `instance.lock` 再写入，多个进程可能同时判断锁空闲；写锁失败还会继续启动。结果可能有两个写入者同时改状态和笔记。 | 设计原子抢锁、失效锁处理与故障降级，加入多进程测试；需要确认锁损坏时是拒绝启动还是进入只读模式。 |
| 高 | **下载程序的来源校验不完整。** [whisper.js](../core/lib/whisper.js) 的 ffmpeg 下载仅验证文件可运行；[menubar/build.sh](../menubar/build.sh) 下载 Node 未校验摘要；[ytdlp.js](../core/lib/ytdlp.js) 可能从镜像取得程序及其摘要，缺乏独立可信校验。 | 确定各来源的固定版本和可信摘要／签名获取方式，并在校验失败时停止执行。需要兼顾国内网络与离线构建体验。 |
| 中 | **存档重整理可能仍会重新抓取或转写。** [index.js](../core/lib/index.js) 在取用传入字幕前仍会走平台内容抓取，缓存失效时可能触发网络或转写。界面和文档的绝对保证已纠正。 | 拆分元数据获取与字幕获取，明确存档模式是否允许联网、应如何填补缺失元数据，再增加不联网的回归测试。 |
| 中 | **文件系统隔离仍有边界。** [obsidian.js](../core/lib/obsidian.js) 已拒绝 `..` 越出 vault，但没有验证目录中的符号链接最终指向；[vault-access.js](../core/lib/vault-access.js) 的超时不能取消已启动的底层 I/O，超时后旧操作仍可能晚于重试完成。 | 明确是否支持 vault 内指向外部的符号链接；评估真实路径校验和可终止的子进程 I/O，同时处理检查与写入之间的竞态。 |
| 中 | **批量写入仍非事务。** 标签合并逐篇成功后已即时保存状态，减少中途失败的不一致；但 [index.js](../core/lib/index.js) 中笔记写入与状态保存仍是独立操作，部分保存错误只记日志。磁盘满或中断时仍可能不一致。 | 为复习、标签合并等操作设计可恢复日志或显式的部分成功结果，并确定失败后的重试／修复入口。 |
| 中 | **知识库搜索会静默漏掉内容。** [vault-search.js](../core/lib/vault-search.js) 最多遍历 2000 个文件、6 层目录、跳过大于 200 KiB 的文件，逐文件串行读取；查询只按空格拆词，较长中文自然语言通常被当作一个完整词。 | 决定大库是否需要增量索引、分词和并发限制；在结果被截断时向用户提示。 |
| 中 | **学科上限可能导致错误归类。** [subject.js](../core/lib/subject.js) 到达 12 个学科后，即使没有相似字符也会强行归入某个已有学科。 | 决定放宽上限、归入「未分类」还是让用户确认；旧笔记是否重新分类需要另行评估。 |
| 中 | **局域网监听缺少身份认证。** [server/index.js](../server/index.js) 默认仅监听 `127.0.0.1`，但若显式设置 `SEEN_HOST` 为非本机地址，网络上的客户端可直接调用服务接口。浏览器同源检查并不能替代客户端身份认证。 | 明确是否需要远程访问；若需要，设计认证、传输保护及密钥管理后再开放。兼容用的 `GET /api/llm/models` 仍允许调用者把自带密钥放进 URL，建议逐步废弃。 |
| 低 | **构建备份持续占空间。** [menubar/build.sh](../menubar/build.sh) 每次轻量构建都会保留旧 app；本次核查时 `menubar/build/previous-app.*` 共 46 份，约 5.3 GiB。它们被 Git 忽略，现有设计草稿也被保留。 | 用户确认需要保留的版本和清理范围后再处理；不自动删除，后续可约定保留数量或单独归档。打包/安装脚本也含覆盖或删除操作，运行前应先审查目标路径。 |
